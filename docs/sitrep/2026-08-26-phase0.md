# Sitrep — 2026-08-26 — Phase 0 framework

## What this session did

Converted the repo from a plain pyedgeconnect fork into the `pyecsdwan` project:
a transactional CLI abstraction layer for EdgeConnect SD-WAN (see
`docs/plan-phase0.md` for the design decisions and mined endpoint inventory).

### Landed

- **Knowledge mining** (`docs/research/`): endpoint paths, payload schemas, auth
  patterns, async-job (action key) semantics, save-changes rules, template
  ownership signals — from the vendored pyedgeconnect SDK and EC_SD-WAN_Expert.
  Both OpenAPI 3.0 specs (Orchestrator 870 paths, appliance 437) copied to
  `specs/` as the Tier-1 ingestion baseline.
- **Core framework** (`src/pyecsdwan/`): resource contract
  (Scope/Reversibility/Tier + normalize-centric idempotency), structural diff
  engine, candidate store (Junos candidate-config emulation, per-host on
  disk), crash-safe journal (append-only fsynced JSONL + atomic meta),
  transaction engine (snapshot-before-write, dependency-ordered apply,
  verify-after-apply, partial-failure auto-revert, guards for
  IRREVERSIBLE/tier/ownership/API-key), detached double-fork watchdog for
  `commit confirm`, rollback history, orphan recovery, httpx client
  (X-Auth-Token, GET-only retries, redacting structured logs), resolver cache,
  action-key poller (array responses, unreliable completionStatus handled).
- **Trivial resource**: `interface-labels` (GET/POST /gms/interfaceLabels,
  REVERSIBLE, field-verified endpoint) proving the full loop.
- **Mock Orchestrator** (`pyecsdwan.mock`): FastAPI fake with appliances,
  interface labels, template groups + association + action log, overlays +
  association, securityMaps; `python -m pyecsdwan.mock` or in-thread for tests.
- **CLI**: typer subcommands (set/delete/load/diff/commit/confirm/rollback/
  show/api/cache) + prompt_toolkit Junos shell (operational + config modes,
  completion, `show | compare`, `commit confirm N`).
- **Tests**: unit (diff/candidate/journal/registry/client/jobs/resource),
  transaction engine (idempotency, ordering, partial-failure revert, guards,
  orphan recovery, rollback history), watchdog (foreground + real detached
  daemon e2e against the mock: auto-revert on expiry, confirm honored).
- **Packaging/conventions**: PEP 621 pyproject (`ec-cli`/`sase-cli`
  entrypoints, pinned deps), Makefile (`make install`, `make check`), README
  rewrite (original SDK README moved to `docs/pyedgeconnect-README.md`),
  `docs/plugin-promotion.md`, `docs/watchdog-backends.md`, `docs/futures/`.
  pyedgeconnect's setup.py/MANIFEST.in removed (metadata conflicted with the
  new root project); the SDK source stays vendored as reference.

### Notable decisions

- Ownership detection = template association × template selection join, plus
  `gms_marked` where the API has it (no per-section managed-by field exists).
- `commit confirm` refuses interactive-login auth (watchdog can't replay it)
  and auto-reverts if the watchdog fails to arm.
- Failed step k is reverted along with steps 1..k-1 (its write may have
  partially landed).
- Job success keys on `taskStatus` text; `completionStatus` only as tiebreaker.

### Infrastructure note

The Workflow-tool subagent path was broken in this environment (permission
handler mangled tool inputs; StructuredOutput validation failed for all 5
miners). Fanned out via the Agent tool instead — plain agents worked fine.
