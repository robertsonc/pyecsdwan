The source of record for the `live-read-verified` entries in
`src/pyecsdwan/_evidence/ledger.json`. Everything here was observed, not
inferred; where something is inferred it says so.

## What was run

A read sweep over every curated kind. Per kind, per reachable appliance:

1. `list_refs()`
2. `fetch()`
3. `normalize()`, then `normalize(normalize(x)) == normalize(x)`
4. a canonical state diffed against **itself**, asserted empty

Step 4 is the read-only half of the level-4 no-op proof: it shows the resource
does not manufacture drift out of its own output. It is *not* level 4, which
requires actually committing unchanged state back.

**Result: 41 curated kinds, 0 idempotency failures, 0 phantom drift.**

38 kinds are promoted to `live-read-verified`. Three are not:
`appliance/vrrp`, `security-policy` and `ip-service-group` returned zero refs
because nothing of that kind is configured here — there was nothing to read,
which is not the same as reading it successfully.

## What this does not claim

**No write path has been verified.** One BGP write was executed and reverted
(below), and it did not produce level-4 evidence: the poller could not classify
the response, so nothing about the write was confirmed at the time. Every write
in this repository remains code that has not met a fabric.

## Defects found

**The save-changes poller did not recognise 9.7's success shape.** A BGP
neighbour write reached the fabric and was saved; the poller saw
`taskStatus='COMPLETED' result='Saved change on appliance successfully'`,
matched no allowlisted shape, and returned UNKNOWN. The engine treated the
apply as failed and auto-reverted — and the revert hit the *same* unrecognised
shape, reporting `REVERT_FAILED`. The fabric was correct throughout: both the
apply and the revert really happened, verified byte-identical against a
pre-change baseline. Fixed, with the shape recorded in
`docs/research/job-shapes.md`.

**Template ownership was wrong in both directions.** Full analysis in
`docs/research/live-ownership-2026-08-30.md`; the model and the owner's
decisions are `specs/004-ownership-granularity/spec.md`. In short: five kinds
named template sections this Orchestrator has never heard of and therefore
could never detect an owner (`optimization-map` looked for `optimizationMaps`
where the real section is `optmap`, which demonstrably pushes); and ownership
was keyed by resource kind where real authority is per field and per priority
band, so locally significant changes — BGP peers — were refused.

**A cache-key collision I introduced during the rework.** `ownership` cached
full template-group bodies under the key `Resolver.template_groups()` already
owned for a list of names. `template-group.list_refs` then built refs whose
name was an entire group object. Only the sweep hit it, because it needs both
callers in one process in one order.

**Three live-only tests had never executed anywhere.** They called
`config.load_settings()`, which does not exist, and were gated on
`ECSDWAN_ORCH_URL` — so no mock-only host ever ran them. They also fetched
every ref `list_refs` returns, including unreachable appliances.

## What the tool got right

`drift` degrades correctly on an incomplete fabric. With two appliances
unreachable it reported `unreadable: 2` and refused to claim "no drift":

```
drift: 0  in-sync: 0  undeclared: 4  unreadable: 2
incomplete: 2 instance(s)/scope(s) could not be compared, so "no drift" is not
a claim this run can make                                          exit 8
```

That is spec 003's T9 criterion — "list failure is incomplete" — satisfied with
live evidence rather than mock evidence.

## Re-reading this

The sweep is `/tmp/ec-live/sweep.py` in the session that produced it; it is
short enough to re-derive from this description and depends on nothing but the
registry and a configured client. The captured template bodies and appliance
payloads were not committed — they carry lab addressing and would age into
misleading fixtures. `docs/research/live-ownership-2026-08-30.md` quotes the
specific values every claim rests on.
