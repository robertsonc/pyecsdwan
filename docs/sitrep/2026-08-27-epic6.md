## The shared module came first, and that was the whole ballgame

`#26`, `#27` and `#28` all need to parse the baselines and enumerate
endpoints. Left alone, three workers write three parsers that disagree about
what an endpoint *is*, and the first cross-cutting join fails.

So `src/pyecsdwan/specs.py` was written and merged **before any brief went
out** — coordinator-owned, off every worker's surface, with a STOP rule if
anyone needed to change it. Nobody did.

The load-bearing piece is `normalize_path()`. Four sources spell path
parameters four ways:

| source | spelling |
|---|---|
| OpenAPI baselines | `/appliance/{nePk}` |
| Postman, appliance folder | `/appliance/:nePk` |
| Postman, orchestrator folder | `/appliance/{{nePk}}` |
| appliance resource modules | `bgp/config/system` (relative, no leading slash) |

All four collapse to one key, so #51's payload examples, #28's resource
declarations and #26's codegen all join without negotiation. When #51 merged,
#28's `example` column lit up with no coordination between the two workers.
That is what the module was for.

Also in it: bounded, cycle-safe `$ref` resolution. EdgeConnect's component
schemas are mutually recursive — a template contains templates — so an
unbounded resolver never returns. Depth-capped at 6, deeper refs left as
`$ref` markers.

## Corrections from workers — four for four

This is the fourth epic where briefing workers with verified facts up front
paid for itself, and the second where the *worker* caught the coordinator.

**#51 — two of my measurements were wrong, one materially.** I claimed 204
untyped write operations (159 fillable) and 802 untyped responses (151
fillable). Measured with the package's own API rather than my ad-hoc script:
**169 (128 fillable)** and **667 (21 fillable)**. Two causes: my script read
only `requestBody.content[].schema` and missed the Swagger-2 `in: body`
parameter form the baselines also use; and it read only the `200` response
with no `default` fallback.

The third figure is the one that changes a decision. Of 1162 response
examples in the collections, **1141 land on operations the specs already
type** — only 21 fill a gap. **The response half of that data is close to
worthless and nobody should build on it.** The request half is the reason to
have it at all.

**#29 — my suggested sample source was the worse one.** I proposed proving
idempotency from `specs.payload_example()` + `Resource.endpoints`. The worker
used the bundled mock plus each resource's own `fetch()` instead: real
captured fixture values rather than the vendor's `"string"` / `0` / `true`
placeholders, and it exercises the read path rather than bypassing it.
Payload examples seed exactly one case, flagged shape-only.

**#26 — my map-key heuristic was insufficient.** I said "all-numeric keys or
`<angle-bracket>` keys means the block is a map, not a record." That misses
`GET /tunnels2/bonded`, whose response properties are literally
`['1.NE', '2.NE']` — nePk-shaped keys that emit `class 1Ne`, not valid
Python. Extended to appliance primary keys (the shape `validate_ne_pk`
enforces) and IPv4 literals. The bracket test also had to become one-sided,
because the baselines contain `VrfId1>` and `<pppoeName>>`.

**#27 — acceptance criterion 3 is not testable where the issue says.** The
issue asks that a stub "refuses `commit confirm` without
`--allow-untransactional`". But `txn.build_plan()` calls `normalize()` on
every candidate, so a Tier-1 stub **cannot enter a plan at all** — it dies
before the confirm guard is ever consulted. Tested at `txn._guard`, the layer
that actually encodes the rule, and documented plainly rather than papered
over.

Every one of these was argued from the specs or the code, not asserted. The
briefs explicitly invite it ("if any instruction turns out to be wrong, say
so explicitly and argue from evidence"); keep that sentence.

## What shipped

**#26 — models + bindings.** `tools/gen_models.py`, per-operation. Policy
lives in one hand-written `generated/_base.py`: `extra="allow"` for drift
tolerance, `by_alias`/`exclude_unset` on dump, ECOS paths emitted relative.
`self` (98 occurrences) is **emitted** as `self_` with `Field(alias="self")`,
not dropped — the resource layer strips it as intent noise, but codegen's job
is fidelity, and `security_policy.py` re-injects those echoes on POST, so a
model that dropped it would corrupt a read-modify-write.

**#27 — Tier-1 stubs.** `tools/gen_plugin.py` builds its binding call by
*parsing gen_models' own rendered signature* rather than re-deriving its
rules, so the two tools cannot drift. Reversibility is declared from what the
spec offers: COMPENSABLE only for a write with a paired GET on the same path;
IRREVERSIBLE otherwise. **A paired DELETE alone never buys COMPENSABLE** —
without a GET the stub cannot tell a create from an update, so "compensating"
an update by deleting would destroy live config. Never REVERSIBLE: nothing in
a spec promises the GET response is accepted verbatim by the write.

**#28 — coverage over the universe.** One optional `Resource.endpoints`
attribute, 119 declarations across all 41 kinds, and a test asserting every
declaration resolves in a spec. Last epic, seven issue-named paths existed in
neither baseline (pyedgeconnect module names mistaken for REST paths), caught
only by hand-grepping. That class is now unmergeable.

**#29 — enforceable promotion.** `tests/test_promotion.py` parametrizes over
the live registry, so a kind is covered the moment it registers. The
anti-vacuity rule is what makes it real: `{"templates": {}}` is a truthy dict
on which `normalize(normalize(x)) == normalize(x)` holds for free, so the gate
counts **leaf values**, not container truthiness — which caught two kinds that
canonicalize to exactly that shell. 41 of 41 kinds by direct property check,
opt-out list empty *and asserted empty*.

**#51 — payload examples.** Rescoped, see above. `tools/postman_sync.py` →
`specs/payload-examples-9.6.json`, 1794 endpoints, ~1 MB, keyed by the shared
endpoint key.

## The seam bug: two green epics, one wrong answer between them

`ec-cli plugin promote` (from #29) gated the Tier-2 idempotency checks behind
`tier >= CURATED`. For a Tier-1 stub that left exactly one box evaluated —
"un-curated kinds must refuse" — which passes *precisely because the stub is
still a stub*. The command then printed "every machine-checkable box is green
… set `tier = Tier.CURATED`".

Following that advice produces a Tier-2 kind whose `normalize()` raises.
`make check` rejects it, so nothing unsafe could ship — but it is the one
command a curator is pointed at, and the advice was backwards.

Neither issue was wrong on its own. The branch was **unreachable** when #29
merged, because no Tier-0/1 kind was registered anywhere; #27's stubs made it
reachable an hour later. #27's worker found it and correctly filed it rather
than reaching into `cli/`; fixed at integration.

Worth generalizing: **when a gate has no live occupants, its untaken branches
are untested by construction.** #29 anticipated half of this and proved its
assertions against constructed stubs — but the *CLI wrapper* around those
assertions had no such fixture. Check the wrapper, not just the check.

## Verification technique worth reusing

Both codegen workers, independently: generate **everything** into the tree,
run the full gate over it, then reduce to a handful of committed samples.

- #26: all 1833 operations → ruff, `ruff format --diff`, mypy `--strict`
  clean over 3670 files → reduced to 8 samples.
- #27: all 837 generatable write operations → same over 3355 files → reduced
  to 2 samples.

#27's sweep found four emitter bugs that hand-picked endpoints would have
missed, including a query parameter typed `integer` on one operation and
`string` on another of the *same path*. Hand-picking test cases for a code
generator tests the cases you thought of.

## What is NOT verified

Unchanged from epic #4 and worth restating, because the test count keeps
growing: **every write path from epics #3 and #4 is spec-confirmed but has
never executed against real gear.** All live access this session and last was
read-only by design.

New to this epic: **no generated Tier-1 stub has ever been executed at all**,
against a fabric or the mock's write paths. They compile, register, refuse to
normalize, and are proven inert in the transaction engine. Their `apply()`
and `rollback()` paths are untested by anything but their own emission.
That is the correct state for Tier 1 — it is why `normalize()` raises — but
do not read "5 generated" in `show coverage` as "5 usable resources".
