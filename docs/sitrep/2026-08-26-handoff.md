## How to work

```bash
make install     # .venv + ./ec-cli symlink (no sudo)
make check       # ruff + mypy --strict + pytest — the gate; keep it green
pytest -m "not slow"   # skip the ~20s detached-watchdog e2e

# exercise the CLI with no real Orchestrator:
python -m pyecsdwan.mock --port 8477 &
ec-cli --mock 8477 shell

# against a real Orchestrator:
export ECSDWAN_ORCH_URL=<host>   # e.g. tme-lab14-...silverpeak.cloud
export ECSDWAN_API_KEY=<key>     # or OS keyring
ec-cli show appliances
```

Note: the CLI must run on a host with network line-of-sight to the
Orchestrator. This cloud build sandbox generally can't reach a private/lab
Orchestrator — develop against `--mock` here, test against real gear from a
reachable host.

## The model in one paragraph

Every configurable object is a `Resource` (`contract.py`) with a `kind`,
`scope` (ORCHESTRATOR/APPLIANCE), `reversibility` (REVERSIBLE/COMPENSABLE/
IRREVERSIBLE), and `tier` (0 raw / 1 generated / 2 curated). It implements
`fetch → normalize → diff → apply → verify → rollback` plus a `managed_by()`
template-ownership hook. **`normalize()` is where idempotency lives** — strip
server IDs/defaults, sort lists stably, resolve names↔IDs via the resolver;
diffing raw JSON is forbidden. `set`/`delete` accumulate in a candidate store;
`commit` snapshots to a crash-safe journal, applies in dependency order,
verifies, and auto-reverts on partial failure; `commit confirm <min>` arms a
detached watchdog that reverts unless confirmed. Tier-0 `ec-cli api` reaches
any endpoint today, journaled but outside the transaction.

## Adding a resource (the Phase-2 loop)

1. New file in `src/pyecsdwan/resources/`, subclass `Resource`, set the class
   attrs, implement `fetch`/`normalize`/`apply`/`rollback` (`diff`/`verify`
   have working defaults). Register it in `resources/__init__.py`.
2. Appliance-scope: write through the proxy
   (`ctx.client.appliance_request(method, ne_pk, ecos_path, ...)`), then
   **save-changes** (see #11), and wire `managed_by()` to `ownership.py`.
3. Extend the mock (`src/pyecsdwan/mock/server.py`) with the endpoint so it's
   testable, then add an e2e test to `tests/` mirroring `tests/test_phase1.py`
   (idempotency round-trip + rollback + partial-failure).
4. `make check` green. Promotion checklist: `docs/plugin-promotion.md`.

Copy `resources/security_policy.py` (self-echo inject/strip, segment-pair
name validation) or `resources/overlays.py` (name↔id resolution,
canonicalize_desired, set-delta associations) as templates.

## Known small polish items (not blocking, worth a cleanup PR)

- `set appliance <name> <kind> …`: today there are **no appliance-scope kinds**
  (Phase 2 adds them), and the usage line doesn't explain that `interface-labels`
  et al. are orchestrator-scoped or that a name/path/value is missing. Improve
  the error to name the scope mismatch / missing args. (Surfaced live this
  session.)
- Client timeout UX: a `GET` retries 3× with backoff on top of a 9s connect /
  30s read timeout, so an unreachable Orchestrator hangs ~50s+ before failing,
  and the shell shows only a debug line. Make it fail fast + legibly: shorter
  overridable connect timeout, no blind retry on connect-timeout, clean
  "cannot reach Orchestrator <host>" message. (`client.py` + shell error path.)

## Guardrails (things a new session must not break)

- `contract.py` is the frozen plugin contract — extend, don't reshape.
- `normalize()` idempotency is the acceptance test: same command twice ⇒ "no
  changes", zero write calls.
- Never let Tier-0/1 silently enter a `commit confirm` changeset.
- Host-scope every journal/recovery lookup (a snapshot from one Orchestrator
  must never restore into another) — see the review-fix commits.
- Secrets never on argv, never unredacted in logs/journal; state files 0o600,
  dirs 0o700.
