## The headline finding: the epic was mis-scoped

Before dispatching anything I checked every endpoint named in the nine
issues against both vendored specs, then probed a live lab Orchestrator
read-only. Two systematic problems:

**1. Most write paths are on the appliance, not the Orchestrator.** These
are all **GET-only** on the Orchestrator API: `/acls`, `/nat*` (every
variant), `/shaper`, `/inboundShaper`, `/qosMaps`, `/optimizationMaps`,
`/routeMaps`, `/snmp`, `/logging`, `/banners`, `/mgmtServices`,
`/dnsProxy/config`. Every one has a GET+POST twin in
`specs/appliance-openapi-7.2.0.json`, reachable through the
`/appliance/rest` proxy. So #31's ACLs, all of #32, all five of #33, and
four of #38's five shipped **appliance-scope**.

This is the same trap #16/#17 (BGP/OSPF) hit last session, where "no write
endpoint exists" turned out to mean "no write endpoint exists *on the
Orchestrator API*". Checking both specs — not just the one the issue implies
— is now a standing pre-dispatch step.

**2. Several issue-texts named paths that don't exist anywhere.**
`/route_policy`, `/optimization_policy`, `/nat_policy`, `/vrf_snat_maps`,
`/vrf_dnat_maps`, `/acls/{name}`, `/dependency/acl/{name}` (at orchestrator
scope), `/third_party_services`, `/services`. These are **pyedgeconnect SDK
module names**, not REST paths — the issues were written from the SDK's file
layout rather than from the API. Corrected paths are in each module
docstring.

## Traps found pre-dispatch, and how they landed

- **`match.overlayAcl` is a JSON-encoded string** inside the regional overlay
  config (#35). Diffed opaquely it would drift permanently the first time the
  server re-serialized with different key order. Now parsed into canonical
  state and re-encoded with `sort_keys` on write; proven by a shuffled-key
  round-trip test.
- **`setSubnetSharingOptions` is POST-only with no read path anywhere**
  (#37). A write-only endpoint can't be a Tier-2 resource — no read means no
  snapshot, diff, or rollback. Documented as not modelable rather than faked.
- **`activeMap` in the `data`/`options` envelope** (#32, #33). The live
  `options` block carries a third key `security_policy.py` doesn't send, and
  it names *which map is live*. Omitting or blanking it on a full-table
  replace would deactivate the operator's running map as a side effect of an
  unrelated rule edit. Both workers independently converged on: lift into
  canonical state, back-fill from the server when intent is silent, omit
  entirely rather than send `""`.

## Findings that came back from workers

- **My dispatch brief for #36 was wrong.** I told the worker the overlay
  priority map was `overlayId → priority`; it's `priority → overlayId`. I'd
  inferred it from the live capture `{"1":1,"2":2,"3":3,"4":4}` — the
  identity permutation, which reads the same in both directions and was never
  evidence. The worker checked the OpenAPI descriptions, the vendored SDK
  docstrings, and this repo's own research doc, found all three said the
  opposite, implemented correctly, and documented the argument. Verified
  before merging. **Lesson: don't ground a directional claim on a symmetric
  sample.**
- **`security_policy._inject_self` is not generic — three workers found this
  independently.** It hardcodes the map → zonePair → `prio` → rule nesting,
  so on any shallower shape it writes the echo into the wrong container
  (`self: "prio"` into a NAT priority table, `self: "entry"` into an ACL
  entry container). #31, #32 and #33 each wrote a correct-depth variant and
  pinned the divergence with a regression test. `_strip_meta` by contrast is
  genuinely generic and was reused verbatim everywhere. Filed as framework
  friction.
- **A latent bug in `interface_labels.py`** (#39): `deleteDependencies` was
  hardcoded `true` on every forward write, so a pure add or rename silently
  cascaded into port profiles and templates. Now defaults `false`, opt-in.
- **First live-confirmed template section names** (#38), which is direct
  progress on #20. A real Default Template Group selects: `adminDistance`,
  `cli`, `dns`, `datetime`, `logging`, `mgmtServices`, `routes`,
  `secureWebServicesConfig`, `shaper`, `snmp`, `webconfig`. So `snmp`,
  `logging`, `mgmtServices`, `dns`, `shaper`, `routes` are now confirmed in
  `ownership.KIND_TO_TEMPLATE_SECTIONS` (and marked as such, to distinguish
  them from the surrounding guesses); `datetime` is unclaimed and awaits an
  NTP/time resource.

## What's NOT verified

Worth stating plainly, because the test count makes it easy to over-trust:
**every write path in this epic is spec-confirmed but has never been
executed against real gear.** This session's live access was read-only by
design. Before any of these touches production, do a no-op round trip first
— GET current state, commit it back unchanged, confirm the re-plan diffs
empty. `docs/futures/README.md` §"Write semantics needing live confirmation"
lists the specific uncertainties (PUT merge-vs-replace on regional overlays,
natPools replace-vs-merge, `POST acls` with `merge=false`, the real
`options` key set, `segmentedIpv6Enabled` on write).

The same caveat still applies to #16/#17's BGP/OSPF write path from last
session.

## Process notes for next time

- **The `resources/__init__.py` conflict is now fully solved.** Telling
  workers "edit it, then run `ruff check --fix` and let isort settle it"
  worked — every conflict this epic was a trivial keep-both, and `git rerere`
  replayed most of them. Much better than the per-line `noqa` improvisation
  last session produced.
- **`mock/server.py` and `ownership.py` conflict on every parallel merge.**
  All were keep-both, resolved mechanically (a regex that keeps both sides of
  an additive hunk handled all of them). Worth considering per-resource mock
  modules if a future wave runs wider than 4.
- **Pre-dispatch endpoint verification is the highest-leverage step in this
  whole workflow.** ~20 minutes of spec-grepping and read-only probing
  reshaped the entire epic (appliance-vs-orchestrator scope), caught three
  traps that would each have been a silent correctness bug, and let every
  brief carry real payload shapes instead of guesses. Do it before writing a
  single brief.
- **Workers pushing back on the brief is working as intended** — #36's
  direction correction and #39's rejection of both approaches I suggested
  were both right, and both were argued from evidence. The briefs explicitly
  invite this ("if you find a reason that doesn't work, say so explicitly");
  keep that.
